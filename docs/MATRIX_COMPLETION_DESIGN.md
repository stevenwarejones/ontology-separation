# Matrix completion design

The original registry confuses an implemented probability interface with a complete
physical universe. This revision separates three layers:

1. Native results: a bound or witness derived from the original model definition.
2. Explicit experimental extensions: additional laws, a restricted protocol, and
   a theorem about that protocol. These are never silently attributed to a column.
3. Missing-law analysis: an independent experimental sector can be freely added
   without changing an existing behavior. A constructive Lean theorem proves
   this underdetermination; it is not a proof about every physical completion.

A blank cannot responsibly become a unique prediction solely by changing a
status label. The main matrix will retain this distinction while every original
research scenario receives a concrete mathematical subproblem and checked result.

Shared infrastructure: finite probability distributions, setting restrictions,
independent sectors, binary readouts, and finite randomized decoder contracts.
The existing Bell and LF models retain their meanings. Model refinements must
preserve public probabilities. Numerical examples are witnesses, not optima.

Research subproblems:
- P01: three pairwise binary records; global gluing imposes triangle bound 2.
- P03: contamination fraction in LF; derive a robust score lower bound on the
  fraction outside the LF class, without equating that fraction to communication.
- P05: parity-encoded records; restricted versus joint access and passive relabeling.
- P06: a Pauli X/Z order-interference calibration, not certification of general
  causal nonseparability or a friend-order theorem.
- P07: a real controlled-phase entanglement test; product-amplitude obstruction,
  not a model-independent quantum-gravity test.
- P08: one classical bit query versus two for two-bit parity, including randomized
  response functions; not a lower bound against coherent quantum queries.
- P10: pairwise agreement errors bound end-to-end disagreement, with a public
  joint record assumption; no automatic composition of inaccessible views.

Examples: generate the model matrix plus one page per experiment. Each page shows
all sixteen ontology requirement profiles, with selectable two-axis slices and
explicit definitions. Profile syntax is not physical realizability; prediction
rules need a proved bridge between each physical predicate and the experiment.
Do not populate profile cells from arbitrary Boolean tags on a numerical simulator.

Portability: separate Lean Tests/ from python_tests/, enforce case-fold-safe paths,
and fail if Python test discovery finds zero tests. Generate all HTML under examples/.
